② 为什么需要 Attention 视角

梯度视角的局限

梯度统计（R_A, R_B, R_dW）回答的是：参数更新时文本 token 贡献更大还是视觉 token 贡献更大？

但它无法回答：在推理时，模型实际上是否在「看」视觉内容？

Attention 视角补充的内容

指标过文本化时的预期表现
$A_{tv}$（文本 query → 视觉 key） 偏低：文本 token 不关注视觉内容
$A_{tt}$（文本 query → 文本 key） 偏高：文本 token 形成自闭回路
$A_{vt}$（视觉 query → 文本 key） 偏高：视觉 token 被文本强烈吸引
$A_{vv}$（视觉 query → 视觉 key） 偏低：视觉自注意力被削弱
核心信号：$R_\text{att-text} = A_{tt} / (A_{tt} + A_{tv})$ 随任务序号递增，说明持续学习让 text token 越来越忽视 visual 内容。

③ 指标定义

四个注意力预算占比

对每个 (head, query)，先对目标模态的全部 key 求和，得到该 query 分配给此模态的"预算占比"，再对所有 (batch, head, query position) 取均值：

$$A_{tt} = \mathbb{E}_{b,h,q\in\text{text}}\!\left[\sum_{k\in\text{text}} w_{bh,q,k}\right]$$ $$A_{tv} = \mathbb{E}_{b,h,q\in\text{text}}\!\left[\sum_{k\in\text{vis}} w_{bh,q,k}\right]$$ $$A_{vt} = \mathbb{E}_{b,h,q\in\text{vis}}\!\left[\sum_{k\in\text{text}} w_{bh,q,k}\right]$$ $$A_{vv} = \mathbb{E}_{b,h,q\in\text{vis}}\!\left[\sum_{k\in\text{vis}} w_{bh,q,k}\right]$$

其中 $w_{bh,q,k} = \text{softmax}(QK^T/\sqrt{d})_{bh,q,k}$。padding key 被 attention mask 置 $-\infty$，softmax 后权重 $\approx 0$，因此：

$A_{tt}+A_{tv} \approx 1$   $A_{vt}+A_{vv} \approx 1$

两行各自加和为 1，由 softmax 归一化性质直接保证，无需额外归一化步骤。

两个派生比值

列名公式含义
R_att_text $A_{tt} / (A_{tt} + A_{tv})$ 文本 query 注意力预算中分配给文本 key 的比例（$\approx A_{tt}$，因分母 $\approx 1$）
R_att_vis $A_{vt} / (A_{vt} + A_{vv})$ 视觉 query 注意力预算中分配给文本 key 的比例（高 = 视觉被拉向文本）
归一化后 R_att_text ≈ A_tt，直接读 A_tt 列即可判断过文本化程度。与梯度指标 R_A / R_dW 的区别：梯度指标反映参数更新的偏向，注意力指标反映前向传播中信息流动的偏向。两者可能不同步，联合分析更完整。

④ 架构设计

训练路径不变

Attention logging 不修改 attn_output 的计算：

Q, K, V 计算
→
F.scaled_dot_product_attention
→
o_proj → output

logging 路径在 torch.no_grad() 里单独执行，不进入计算图：

同一 Q, K
→
manual softmax (no_grad)
→
attn stats 提取
→
del weights
峰值额外显存：[B=1, H=32, T=2048, T=2048] fp32 ≈ 512 MB，计算完立刻释放。每层顺序执行，不累积。

Token mask 如何传入 LlamaAttention

原有的 _apply_lora_token_mask() 只传给 LoRA 层。AttentionLogger.attach() 对该方法做 monkey-patch，在同一次调用中同时传给所有 LlamaAttention 模块：

attention_logger.py → attach()

orig_apply = model._apply_lora_token_mask.__func__ def _patched_apply(self_model): orig_apply(self_model) # LoRA 层照常传 token_mask = getattr(self_model, "current_lora_mask", None) for module in self_model.model.modules(): if isinstance(module, LlamaAttention): module._attn_token_mask = token_mask # 新增传播 model._apply_lora_token_mask = types.MethodType(_patched_apply, model)
不修改 llava_llama.py，MoEMoKA 分支完全不受影响。

两个 Logger 共用一个 Callback

一次训练里 grad logger 和 attn logger 共享同一个 _StatsCallback，on_step_end 同时递增两个计数器，on_train_end 同时写两份 CSV。
