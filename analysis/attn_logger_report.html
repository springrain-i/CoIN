② 为什么需要 Attention 视角

梯度视角的局限

梯度统计（R_A, R_B, R_dW）回答的是：参数更新时文本 token 贡献更大还是视觉 token 贡献更大？

但它无法回答：在推理时，模型实际上是否在「看」视觉内容？

Attention 视角补充的内容

指标过文本化时的预期表现
$A_{tv}$（答案 text query → 视觉 key） 偏低：答案生成时 text token 不关注视觉内容
$A_{tt}$（答案 text query → 文本 key） 偏高：答案生成时 text token 形成自闭回路
核心信号：$R_\text{att-text} = A_{tt} / (A_{tt} + A_{tv})$ 随任务序号递增，说明持续学习让答案生成 token 在回答阶段越来越少关注视觉内容（指标限定在 post-image text query，排除了系统 prompt 等因因果掩码无法 attend 视觉 token 的位置，详见附录 B-1）。

③ 指标定义

两个注意力预算占比

测量背景（teacher forcing 训练正向传播）：训练时整条序列一次喂入：

[sys-prompt text] → [user instruction text] → [576 visual tokens] → [answer tokens (GT)]

因果掩码保证位置 $q$ 只能 attend 到位置 $\le q$ 的 K，但所有位置的 Q 同时计算（非自回归逐步生成）。
指标限定在 post-image text query，即最后一个 visual token 之后的答案 token 位置。

对每个这样的 query 位置 $q$，将其 softmax 权重按 key 的模态分组求和：

$$A_{tt} = \mathbb{E}_{b,h,q\in\text{post-img-text}}\!\left[\sum_{k\in\text{text},\,k\le q} w_{bh,q,k}\right]$$ $$A_{tv} = \mathbb{E}_{b,h,q\in\text{post-img-text}}\!\left[\sum_{k\in\text{vis}} w_{bh,q,k}\right]$$

其中 $w_{bh,q,k} = \text{softmax}(QK^T/\sqrt{d})_{bh,q,k}$，post-img-text $= \{q : q > \text{last-vis-pos},\; \text{token-mask}[q]=2\}$。

⚠ text key 的范围：token-mask = 2 标记所有文本位置，包括 sys-prompt、用户指令，以及位置 $q$ 之前的答案 token。因此 $A_{tt}$ 含有"答案 attend 到自身之前答案"的权重。
对序列中第一个答案 token，text key 只含 sys-prompt + 用户指令，此时 $A_{tt} + A_{tv} = 1$（无 padding）。对后续答案 token，text key 中额外包含前若干个答案 token。

为什么是 $\approx 1$ 而不是 $= 1$？
对任意 query，softmax 权重在所有 K 位置（含 padding）上精确求和为 1： $$A_{tt} + A_{tv} + A_{t,\text{pad}} = 1$$ padding 位置被 attention mask 置为 $-\infty$，理论贡献为 0，但 float32 中 $e^{-\infty}$ 有极小 subnormal 误差（$< 10^{-7}$），故：

$A_{tt}+A_{tv} = 1 - A_{t,\text{pad}} \approx 1$（实际偏差 $< 10^{-7}$，可视为等于 1）

派生比值

列名公式含义
R_att_text $A_{tt} / (A_{tt} + A_{tv})$ 答案生成时注意力预算中分配给文本 key 的比例（$\approx A_{tt}$，因分母 $\approx 1$）
R_att_text ≈ A_tt，直接读 A_tt 列即可判断过文本化程度。与梯度指标 R_A / R_dW 的区别：梯度指标反映参数更新的偏向，注意力指标反映前向传播中信息流动的偏向。两者可能不同步，联合分析更完整。

④ 架构设计

训练路径不变

Attention logging 不修改 attn_output 的计算：

Q, K, V 计算
→
F.scaled_dot_product_attention
→
o_proj → output

logging 路径在 torch.no_grad() 里单独执行，不进入计算图：

同一 Q, K
→
manual softmax (no_grad)
→
attn stats 提取
→
del weights
峰值额外显存：[B=1, H=32, T=2048, T=2048] fp32 ≈ 512 MB，计算完立刻释放。每层顺序执行，不累积。

Token mask 如何传入 LlamaAttention

原有的 _apply_lora_token_mask() 只传给 LoRA 层。AttentionLogger.attach() 对该方法做 monkey-patch，在同一次调用中同时传给所有 LlamaAttention 模块：

attention_logger.py → attach()

orig_apply = model._apply_lora_token_mask.__func__ def _patched_apply(self_model): orig_apply(self_model) # LoRA 层照常传 token_mask = getattr(self_model, "current_lora_mask", None) for module in self_model.model.modules(): if isinstance(module, LlamaAttention): module._attn_token_mask = token_mask # 新增传播 model._apply_lora_token_mask = types.MethodType(_patched_apply, model)
不修改 llava_llama.py，MoEMoKA 分支完全不受影响。

两个 Logger 共用一个 Callback

一次训练里 grad logger 和 attn logger 共享同一个 _StatsCallback，on_step_end 同时递增两个计数器，on_train_end 同时写两份 CSV。

附录 B-1：因果注意力混淆修复（供审阅）

来源：review_attn_logger.md · P0 · 已修复于 commit fd15cdb

问题根源

LLaVA 的序列结构如下：

[系统 prompt，100–400 text tokens] → [用户指令前半段] → [576 visual tokens] → [答案 tokens]

因果掩码（causal mask）要求：位置 i 的 query 只能 attend 到位置 ≤ i 的 key。因此，图像之前的文本 tokens 物理上无法 attend 到任何视觉 token，其 softmax 权重对视觉 key 恒为 0：

对 pre-image text token：$A_{tv} = 0$，$A_{tt} \approx 1$ — 这是因果结构的数学必然，不是模型行为。

旧实现对所有文本 query 位置求均值，包含系统 prompt（通常占文本 token 多数）。结果：$R_{\text{att\_text}}$ 被拉高到接近 1，与模型是否过文本化无关，是测量设计缺陷。对比 MoELoRA 和 MoEMoKA 时，两者的 A_tv 均被等幅压低，差异信号被噪声淹没。

修复：限定为 post-image text query

只统计最后一个 visual token 之后的文本 query 位置（即真正的答案生成 token）。这些 token 的因果窗口内同时包含文本 key 和视觉 key，$A_{tv}$ 才反映真实的模态注意力分配。

修复后指标定义：

$$A_{tt} = \mathbb{E}_{b,h,\,q\in\text{post-img-text}}\!\left[\sum_{k\in\text{text}} w_{bh,q,k}\right]$$ $$A_{tv} = \mathbb{E}_{b,h,\,q\in\text{post-img-text}}\!\left[\sum_{k\in\text{vis}} w_{bh,q,k}\right]$$

其中 post-img-text = $\{q : q > \text{last-vis-pos},\; \text{token-mask}[q]=2\}$

代码实现（attention_logger.py · _record）

vis_positions   = v_mask.nonzero(as_tuple=True)[0]
last_vis_pos    = int(vis_positions[-1])

post_img_t_mask = t_mask.clone()
post_img_t_mask[:last_vis_pos + 1] = False   # 排除图像之前（含）的文本

if not post_img_t_mask.any():
    continue   # 该样本无答案 token，跳过

w_tq = w[:, post_img_t_mask, :]          # [H, T_post, T_k]
A_tt = w_tq[:, :, t_mask].sum(-1).mean().item()
A_tv = w_tq[:, :, v_mask].sum(-1).mean().item()
影响：修复前 A_tv 因系统 prompt 强制稀释普遍偏低，两模型差异信号被淹没。修复后，A_tv 反映答案生成阶段真实的视觉注意力分配，可用于论证"持续学习是否加剧过文本化"的核心假设。

附录 B-2：批内聚合方式讨论（供审阅）

来源：review_attn_logger.md · P2 · 当前采用方案 B，欢迎讨论

问题背景

一个 optimizer step 内，batch 中每个 element b 有 $n_b$ 个 post-image text query token，其局部均值为 $A_{tv}^{(b)}$（已在 $H \times n_b$ 个位置上平均）。问题：如何把 $B$ 个局部均值聚合为一个 step 级标量？

方案 A：等权均值（旧实现，已废弃）

$$A_{tv}^{\text{step}} = \frac{1}{B}\sum_{b=1}^{B} A_{tv}^{(b)}$$

语义：每道题（每个 batch element）等权，无论该题有多少答案 token。

A_tv_total += A_tv_b          # 每个 element +1 次，等权
result = A_tv_total / valid_b  # 除以有效 element 数

问题：element 0 有 $n_0=1$ 个答案 token（高方差，如 SciQA 简答），element 1 有 $n_1=50$ 个答案 token（低方差，如 TextVQA 长答案）。等权合并使二者方差不对等，step 级统计噪声偏大。

方案 B：token 加权均值（当前实现）

$$A_{tv}^{\text{step}} = \frac{\displaystyle\sum_{b=1}^{B} n_b \cdot A_{tv}^{(b)}}{\displaystyle\sum_{b=1}^{B} n_b}$$

语义：每个 post-image text query token 等权。等价于在 batch 内所有答案 token 上直接求均值——随机抽一个答案 token，其 $A_{tv}$ 的期望值。

A_tv_wsum         += A_tv_b * n_post   # 按 token 数加权累积
n_post_text_total += n_post
result = A_tv_wsum / n_post_text_total  # 每 token 等权

优点：token 数多的 element 对均值贡献更大，但其局部均值本身也更稳定（方差更小），整体 step 统计量方差降低。

两方案对比（供学长讨论）

维度方案 A（等权，旧）方案 B（token 加权，当前）
分析单位每道题每个答案 token
短答案样本权重与长答案相同按 token 数比例缩小
step 均值方差较大（受单 token 高方差估计影响）较小（token 多的样本贡献更稳定）
CoIN 多任务 task 偏差无隐式 task 偏差TextVQA 等长答案 task 隐式获得更高权重
概率解释"随机抽一道题，其 A_tv 的期望""随机抽一个答案 token，其 A_tv 的期望"
与论文研究问题的匹配"不同 task 的过文本化程度差异""生成 token 时的模态注意力行为"
待讨论：若核心研究问题是"不同 task 之间的过文本化程度是否有差异"，方案 A 的等权语义更合适（每道题等权，避免 TextVQA 长答案主导均值）。若研究问题是"生成过程中模型逐 token 的注意力行为如何随 task 序列演变"，方案 B 更自然。请学长确认分析目标后决定。
