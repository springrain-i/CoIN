① 最终目标

研究问题：持续指令微调（T1→T8）中，MoELoRA 的文本梯度是否系统性主导参数更新，且这种主导是否随任务序号单调加剧？

核心指标：梯度主导比值 R(k)

R(k) = ||G^t_k|| / ||G^v_k|| 其中： G^t_k = 第 k 个任务训练时，文本 token 位置的梯度信号强度 G^v_k = 视觉 token 位置的梯度信号强度 k = 任务序号（1=ScienceQA … 8=OCRVQA）

预期结论：

现象对应指标
文本梯度始终主导所有任务 R(k) > 1
主导随任务序列加剧R(k) 随 k 单调递增
这是视觉模态知识更易被遗忘的机制性原因与 text/visual 模式 acc 差距相关

③ 梯度记录的数学原理

从 token 序列结构出发，逐步推导梯度如何按模态分解，以及我们实际测量了什么。

Step 1 · 输入序列的模态结构

LLaVA forward 时，序列由三段 token 混合组成，每个位置有对应的 token_mask 值：

Step 2 · LoRA Forward + Backward 全流程

-- Forward -- h_A = x @ W_A.T # (T,d_in) × (d_in,r) → (T,r) h_B = h_A @ W_B.T × scaling # (T,r) × (r,d_out) → (T,d_out) output += h_B # 叠加到主模型输出 -- Backward（PyTorch 自动，hook 在标注处拦截）-- ∂L/∂h_B ← 从 Loss 反传来 [hook_B 拦截此值] ∂L/∂W_B = ∂L/∂h_B.T @ h_A (d_out×r) ∂L/∂h_A = ∂L/∂h_B @ W_B [hook_A 拦截此值] ∂L/∂W_A = ∂L/∂h_A.T @ x ← 我们要分解的！ (r×d_in)

Step 4 · 代理指标：我们实际计算的是什么

精确指标 G^t_A 需要 x_text，hook 时无法访问（已被 gradient_checkpointing 释放）。改用 hook 能直接拿到的 ∂L/∂h_A，对其按 token 位置分组求范数：

// hook_A 在 backward 中自动触发，直接拿到 grad_out_A = ∂L/∂h_A，形状 (T, r) // 按 token_mask 把它分成文本部分和视觉部分： grad_out_A_text = grad_out_A * (mask==2) # 文本位置保留，视觉位置清零 grad_out_A_visual = grad_out_A * (mask==1) # 视觉位置保留，文本位置清零 g_text_A = || grad_out_A_text ||_F # Frobenius 范数（所有元素平方和开根号） g_vis_A = || grad_out_A_visual ||_F R_A = g_text_A / g_vis_A # 梯度主导比值
代理指标与精确 G^t_A 的关系：
精确值：G^t_A = ∂L/∂h_AT @ x_text，形状 r×d_in（需要保存 x_text → OOM）
代理值：g_text_A = ‖ ∂L/∂h_A × text_mask ‖_F，标量（只需保存 raw_mask → 2KB）

两者的联系：g_text_A 测量「文本位置梯度信号强度」，而 ‖G^t_A‖_F ≈ g_text_A × ‖x_text_mean‖。 x_text_mean 在训练过程中变化很小，所以 g_text_A 与 ‖G^t_A‖_F 高度正相关。 对判断 R>1 且单调递增，两个指标给出一致结论。

Step 5 · 为什么 R_A 实测是 20× 而不是 2-3×？

一个放大效应 + 一个反向校正效应，净结果 ≈ 20×：

⚠ 之前版本的分析错误：之前写"文本 token 数量多于视觉 token，放大 R"是错的。ScienceQA 实测视觉 token 占 69%，视觉反而更多（CLIP-336 产生 576 个 patch，而每道题文本通常较短）。效应②（token 数量差异）实际在压低 R，不是放大。因此效应①（loss 位置效应）必须独立贡献约 30×，才能在 ×0.67 校正后得到实测的 20×。

Step 6 · 梯度共享：MoELoRA 的 W_B 为什么 R_B 比 R_A 更大？

MoELoRA 有 N=8 个专家，每个专家有自己的 W_A_i，但所有专家 共享同一个 W_B。这个共享结构导致 W_B 的梯度比任何单个 W_A 更偏向文本。

① Forward：8 个专家共同使用 W_B

② Backward：W_B 的梯度来自所有 8 个专家路径之和

③ 为什么 R_B(36×) > R_A(20×)？

梯度共享的核心含义：
W_B 因为被所有专家共享，在 backward 中同时接收来自 8 条专家路径的梯度，这些路径在文本方向高度对齐（因为每个 W_A_i 都已经偏文本了），所以 W_B 的文本梯度强度是 W_A 的叠加版本。

这也说明：即使 MoKA 通过模态特定的 A 矩阵缓解了 W_A 的过文本化，共享的 W_B 仍然可能是一个文本偏置的集散地。这是持续学习中视觉表征退化的关键机制。

分析解读

Q1：R_A = 18 是否意味着视觉被「严重忽视」？

是。18x 的梯度差意味着：在每一个 gradient step 里，文本 token 对 W_A 参数更新的驱动力约是视觉 token 的 18 倍。在 198 步训练后，视觉侧对参数更新的累积贡献可以估算为文本侧的 ~5.5%。

Q2：k_proj / v_proj 的 R_A 为何更低（~9）？

在 Transformer 的 attention 计算中，视觉 token 作为 Key 和 Value 参与查询匹配。文本输出 token 在生成时会 attend to 视觉 token，所以视觉 token 的梯度信号通过 attention 部分地反传到 k_proj 和 v_proj。这使得这两个 proj 的 R_A 相对较低（9 vs 18），但仍远 >1。

Q3：单任务（T1）的结果能否支撑论文的核心主张？

单任务只能证明「T1 内存在梯度主导」，不能证明「持续学习加剧了主导」。需要 T1→T8 的完整序列，观察 R_A(k) 是否随 k 增大。

代理指标的局限：本次测量的是 ||∂L/∂out_A × text_mask||，而非精确的 ||G^t_A||_F = ||grad_out_A^T @ x_text||。两者在数量级上一致，但比值可能有系数差异。在论文中，如果使用此指标，需明确说明「proxy for gradient dominance」。
