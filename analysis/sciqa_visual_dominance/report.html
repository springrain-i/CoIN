ScienceQA 中 Visual LoRA 主导现象

——MoELoRA 持续学习序列中的异常遗忘模式与机制分析

📅 2026-05-27 ⚠ SciQA: 7/7 stages visual > text CoIN 8-task sequence continual_online_eval.csv

§1 现象描述

CoIN 持续指令微调序列中，每个训练阶段结束后采用三种部分模态推理模式评估：

All text LoRA + visual LoRA 同时激活 · Text 仅 text token 位置叠加 LoRA · Visual 仅 image patch 位置叠加 LoRA

对于序列中其他所有任务，Text 模式通常优于 Visual 模式——这与研究假设吻合：文本主导型训练对 visual LoRA 的干扰更大。

唯一异常：ScienceQA
T1 训练结束后，Visual 模式在 T2–T7 的全部 7 个阶段均严格高于 Text 模式。这一优势在 T8（OCR-VQA）后骤然消失，三者收敛至 ~63%。

§3 代码层机制：精确定义

3.1 Token Mask 约定

来源：CoIN/peft/tuners/lora.py:674

Token mask convention (CoIN)
Image tokens IMG_PATCH IMG_PATCH IMG_PATCH → mask = 1
Text tokens Which state is farthest north? → mask = 2
Padding [PAD] [PAD] → mask = 0

3.2 三种模式的精确定义

来源：lora.py:687–692

if lora_mode == "text":
    mask = token_mask == 2      # 只有文本 token 位置叠加 LoRA 增量
elif lora_mode == "vision":
    mask = token_mask == 1      # 只有图像 patch token 位置叠加 LoRA 增量
else:  # "all"
    mask = token_mask > 0       # 所有非 pad token 叠加 LoRA 增量
不同 mode 下 LoRA 激活示意
All mode IMG✓ IMG✓ text✓ token✓ here✓
Text mode IMG✗ IMG✗ text✓ token✓ here✓
Visual mode IMG✓ IMG✓ text✗ token✗ here✗

3.3 重要澄清：不存在"text 专家"或"visual 专家"

来源：coinmoelora.py:389–398

router = self.lora_router[adapter](lora_x)   # nn.Linear(d_in → expert_num)
router = torch.softmax(router, dim=-1)        # (B, S, expert_num)
for i in range(expert_num):
    result += B_i(A_i(lora_x)) * scaling * router[:, :, i].unsqueeze(-1)
路由是软路由（soft routing）：每个 token 对所有 N 个专家计算 softmax 权重，所有专家都被使用，只是权重不同。
不存在预定义的"text 专家"或"visual 专家"——专家角色由训练端到端学习决定。

4.3 Visual Mode 的隐含效应：纯文本题退化为基础模型推理

这是理解 visual mode 优势的核心机制之一。

纯文本 SciQA 题在不同 mode 下的 LoRA 行为
Visual mode Which✗ state✗ is...✗ → mask全False → LoRA=0 → 纯基础模型推理
Text mode Which✓ state✓ is...✓ → 被 T3–T7 污染的 text LoRA 推理

§4b 分层准确率实证：纯文本题 vs 含图题

核心发现：Visual mode 的文本题准确率在 T2–T8 全程固定为 62.72%，这是 LLaMA-7B 基础模型在 SciQA 文本题上的恒定基线。 这一"常数"是 H2 假设（基础模型旁路机制）的直接实证证明。

4b.3 关键解读

核心发现：

发现一 · T3 含图题
T3（ImageNet）后，含图题 All/Text = 8.92%，Visual = 19.39%，两者均低于随机水平（~25%）。 视觉 LoRA 也被严重损伤（−40pp），不存在"受到保护"。Visual 更高的原因是：不叠加已被 ImageNet 彻底破坏的文本 LoRA，避免了额外的错误信号——是"少一个噪声源"的效果。
发现二 · T8 收敛
T8（OCR-VQA）后，All/Text 纯文本恢复至 66.86%，反超 Visual 纯文本 62.72%（+4.14pp）。 T8 的三模式收敛是 All/Text 在纯文本（+20.1pp）和含图题（+13.9pp）上同时恢复带来的，是 All/Text 追上来了，而非 visual 衰退。 Visual 含图仍以 63.26% vs 59.84% 小幅领先（+3.4pp），但已不具决定性。
研究者分析
基于实证数据的逐项深度解读
1 纯文本列

观察上方数据表「Visual 纯文本」列：T1–T8 全程锁死在 62.72%。 同列对比「All 纯文本」：T1=80.71% → T2=62.72% → T3=59.80% → T4=49.24%…… 续训的 LoRA 参数对 SciQA 纯文本题是净负贡献，不是"遗忘了帮助"，而是"主动输出了错误"。 Visual 因为零 LoRA 旁路，反而稳定保持了基础模型的固有能力。

2 Visual 优势 = 文本 LoRA 回避，而非视觉 LoRA 优越

T1 是关键反证：All_img=76.05%，Text_img=75.76%，Visual_img=69.46%——SciQA 训练刚结束时文本 LoRA 干净，All/Text 反而比 Visual 高 6.3pp。Visual 优势不是天然的，而是在文本 LoRA 被污染之后才出现的。

T5 的完整解读：Visual=60.3%，Text=36.4%，All=35.0%。
· Visual >> All/Text：Visual mode 的文本 token 位置不走 LoRA——基础 LLaMA-7B 的多选推理能力完整保留，同时图像 token 的视觉 LoRA 通过注意力提供视觉上下文。
· All < Text（−1.44pp）：两模式均受同等文本 LoRA 污染；但 All mode 额外激活了处于错配状态（ImageNet 覆写后被 GQA 部分修复）的视觉 LoRA，图像 token 表征通过注意力流向文本 token 位置，引入了与文本 LoRA 已有错误叠加的干扰——破坏性叠加比单独的文本 LoRA 略差。

Visual LoRA 对 SciQA 含图题的实际贡献（以 T7 时 visual_img≈62.72% 为基础模型基准估算）：T1 时 +6.74pp（有效学习），T2 起迅速衰减，T4–T7 近乎为零。整个 T2–T7 的 10~25pp 优势全部来自不激活污染的文本 LoRA，视觉 LoRA 本身对 SciQA 的边际贡献已趋于零。

3 T3 ImageNet 数据特性

查看 T3 训练数据（ImageNet/train.json）：
· 129,833 条样本（全序列最大），全部含图
· 唯一问题模板："What is the object? Answer in a single word or phrase."
· 答案格式：单词/短词组，均值仅 1.38 词（65% 单词，32% 双词）

三重叠加灾难：
① 样本量最大 → 梯度更新次数最多，覆写最彻底
② 答案格式极短 → 训练 LoRA 输出对象名词，与 SciQA 的选项字母（A/B/C/D）格式完全冲突
③ 视觉域完全不重叠 → 自然物体照片 vs SciQA 科学图表/地图/几何图形

损伤快速可逆：T4（GQA）后含图题反弹 +30~38pp。

4 Visual LoRA 学到了什么？帮了多少？

视觉 LoRA 确实被持续更新： T1=69.46% → T3=19.39%（ImageNet 覆写）→ T4=57.26%（GQA 修复）→ T7=62.92%——大幅波动证明视觉 LoRA 一直在被各任务主动改写，并非冻结。

但无法量化 LoRA 的绝对贡献： 精确衡量视觉 LoRA 对图像题的净贡献，需要有一次 完全不加 LoRA 的推理作为 backbone 基准（纯文本题的 62.72% 是文本路径的 backbone 基准，但图像题的 backbone 基准未知——视觉编码器参与后模型原始能力可能完全不同）。现有数据中不存在这个对照组。

结论：Visual 模式在图像题上的优势随文本 LoRA 的污染程度同步涨落——T1 时反而不如 Text mode（−6.3pp），T5 峰值时领先 +23.85pp，T8 文本 LoRA 恢复后差距收窄至 +2.43pp。优势的根源是文本 LoRA 回避，而非视觉 LoRA 本身对 SciQA 图像题的专项能力。

§5 机制假设（修订版）

H1
Token 位置梯度不对称——Visual Token 的被动保护
首要假设

精确论点：在文本主导型任务（T2–T7）中，LoRA 专家的参数更新主要由文本 token 位置的梯度驱动。图像 patch token 对最终答案的贡献（以梯度幅值度量）更小，因此 visual mode 路径受到的参数干扰显著少于 text mode 路径。

  • CoIN MoELoRA 所有专家参数被文本和图像 token 的梯度同时更新
  • 但对 TextVQA、GQA、VQAv2，生成正确答案几乎完全取决于文本 token 的正确处理
  • 文本 token 梯度 norm 更大，主导更新方向
  • LoRA 增量逐渐专门化为"处理文本 token 更有效"，图像 token 的增益保持接近 T1 状态
可验证预测：在 T5 checkpoint 上，统计 SciQA 样本中图像 token 与文本 token 位置的梯度 norm 之比，预测 text_grad_norm / vis_grad_norm > 1 且随任务序列单调增大。
H2
纯文本题在 Visual Mode 下退化为基础模型——绕开污染路径
关键机制，与 H1 互补
  • 51.1% 纯文本 SciQA 题在 visual mode 下 = 纯基础 LLaMA-7B 推理
  • 基础模型在语法/常识题上的能力 ≥ 被 T3–T7 污染的 text LoRA
  • T3 时 text acc（30.0%）低于随机，visual mode（41.2%）反映基础模型能力
  • 这不是"visual LoRA 聪明"，而是"text LoRA 主动出错，visual mode 绕开了错误路径"
✅ 已验证（§4b）：Visual 纯文本题 T1–T8 恒为 62.72%（基础模型常数），非 visual 主导而是"零 LoRA 透明"。Visual 在纯文本题上从未优于 All/Text（T8 时 All 纯文本 66.86% 反超）。含图题上 Visual 优势 T2–T7 持续存在（+6~+25pp），T8 收窄至 +3.4pp。H2 的核心机制——零 LoRA 旁路——得到完整验证，但表现形式比预测更极端：不是"集中于某几个阶段"，而是纯文本题在 visual mode 下永久与 LoRA 解耦。
H3
视觉域隔离——图像特征空间正交性
辅助假设

SciQA 的图像（科学图表、几何图形）与后续任务图像（自然照片、场景文字）处于不同视觉特征子空间。即使图像 patch token 的 LoRA 被后续视觉任务更新，更新方向与 SciQA 图表理解正交，实质干扰有限。

T3 ImageNet 关键检验：ImageNet 大量更新图像 token LoRA，visual acc 从 62.7% 跌至 41.2%（−21.5pp），但 T4 后迅速恢复至 61.6%——干扰是局部且可逆的。

可验证预测：在 visual LoRA 权重空间中计算 SciQA 图像样本与 ImageNet/GQA 样本的梯度余弦相似度。预测与 ImageNet 相似度最高，与 GQA 接近零。

T8 收敛现象解释

T7→T8 差距骤缩（+19.55pp → +0.42pp）：OCR-VQA 同时包含视觉落地和语言推理，使 text LoRA 重新学到与 SciQA 兼容的推理模式，text acc 跃升 +19.2pp。Visual acc 几乎不变（+0.11pp）。
收敛由 text LoRA 恢复驱动，而非 visual LoRA 退化。

§6 后续分析建议

  • 最高优先
    Backbone 基准推理：将 LoRA scale 置 0，对 SciQA 图像题跑一次 inference，得到真实 backbone 在图像题上的准确率，可精确量化各阶段视觉 LoRA 的净贡献。
  • 中优先
    梯度正交性度量：计算 SciQA 与 ImageNet/GQA 样本在 visual LoRA 权重空间中梯度方向的余弦相似度，量化视觉域不重叠的程度。
  • 对照实验
    任务顺序对照：将 TextVQA 置于序列首位，观察其 text LoRA 在后续视觉主导任务中是否表现出类似的被动保护效果，验证该原理的可推广性。
