MoELoRA 向量化 Forward
从 8× Python Loop 到 2× einsum

CoIN 使用 MoE-LoRA（混合专家 LoRA），原始实现对 8 个专家逐一串行计算，造成 8× Python dispatch 开销。 optimize 分支将其改写为 2 个 batched einsum，让 GPU 一次性处理全部专家， 推理加速 1.48～1.61×（batch=1，300 样本）。

01

架构总览 — MoELoRA 是什么

MoELoRA = MoE（Mixture of Experts，混合专家） + LoRA（Low-Rank Adaptation，低秩适配）。 对 LLM 中每一个线性层（如 q_proj、v_proj），原始 LoRA 加一对低秩矩阵 A、B； MoELoRA 加 N 对，由一个 Router（门控）动态决定每个 token 用哪几个专家。

LoRA B（8 个）lora_B[adapter].loraB[i].mlp.weight每个 (d_out, r_per) = (4096, 16)✓ 可训练
为什么 LoRA A 是 (r_per, d_in) 而不是 (d_in, r_per)？
PyTorch nn.Linear(in, out) 的权重矩阵存储为 (out, in)，方便做 y = W @ x.T。 所以 A (d_in → r_per) 的 weight 是 (r_per, d_in)，B (r_per → d_out) 的 weight 是 (d_out, r_per)。 einsum 里会用到这个约定。

03

原始 Loop 实现 — 逐行注释

以下是 forward() 中的 LoRA 计算核心部分（optimize 分支的 else 分支，行 ~436）：

# ── 第一步：把输入投影到 LoRA 路径 ──────────────────────────────
# x 原始输入 (B, T, d_in)，先转到 lora_A 的参数 dtype（通常 bf16）
x = x.to(self.lora_A[active].loraA[0].weight.dtype)

# _apply_token_mask: 只对文字 token 或视觉 token 做 LoRA（由 lora_mode 控制）
# lora_x 形状仍是 (B, T, d_in)，但部分 token 已被清零
lora_x, _ = self._apply_token_mask(x)
lora_x = self.lora_dropout[active](lora_x)   # dropout（推理时是 Identity，无效）

# ── 第二步：Router 计算 (B,T,d_in) → (B,T,N) ────────────────────
self.lora_router = self.lora_router.to(lora_x.device)
router = self.lora_router[active](lora_x)   # Linear(d_in, N)，结果 (B,T,8)
router = torch.softmax(router, dim=-1)       # 归一化为权重，每个 token 对 8 个专家的分配比例

# ── 第三步：8 次串行 LoRA 计算 ─────────────────────────────────
# 每次循环：
#   loraA[i](lora_x)  → Linear(d_in=4096, r_per=16) → (B, T, 16)
#   loraB[i](上面)    → Linear(r_per=16, d_out=4096) → (B, T, 4096)
#   × scaling         → 标量乘法 (= lora_alpha / r = 1.0)
#   × router[:,:,i].unsqueeze(-1) → 取第 i 个专家的权重 (B,T,1)，广播
#
# 问题：8 次循环 = 16 次单独 CUDA kernel launch（每次 loraA + loraB 各一次）
#       + 8 次 Python for 循环开销
#       + 16 次 GPU 显存读写（每次 kernel 都要读权重、写中间结果）
for i in range(self.expert_num):   # 8 次串行，无法并行
    result += (
        self.lora_B[active].loraB[i](          # B 矩阵：(B,T,16) → (B,T,4096)
            self.lora_A[active].loraA[i](lora_x),  # A 矩阵：(B,T,4096) → (B,T,16)
        )
        * self.scaling[active]                   # 标量
        * router[:,:,i].unsqueeze(-1)             # 专家权重 (B,T,1)
    )
性能问题的根源
  • 16 次 CUDA kernel launch（每次都有 μs 级的 CPU↔GPU 同步开销）
  • Python 解释器逐行执行循环，GIL 锁住，无法并发
  • 中间结果 (B, T, 16) 反复在 GPU 显存读写（8 次 × 2）
  • GPU 实际利用率低：单个 expert 的矩阵太小（16 维），CUDA core 大量空转
04

向量化实现 — 逐行注释

核心改动：把所有专家的权重 堆叠成 3D 张量，然后用 einsum 一次性完成所有专家的计算。

① 权重堆叠（stack trick）

# ── _lora_vectorized() 方法（行 ~401）───────────────────────────
# active = self.active_adapter（适配器名称，如 "default"）

# 把 8 个 A 矩阵从 list[Tensor(16, 4096)] 堆叠成 Tensor(8, 16, 4096)
A = torch.stack([m.mlp.weight for m in self.lora_A[active].loraA], dim=0)
# m.mlp.weight 就是 CoINMOEExpert.mlp（nn.Linear）的权重矩阵
# 每个是 (r_per, d_in) = (16, 4096)
# stack 8 个 → (N, r_per, d_in) = (8, 16, 4096)
# 注意：stack 在这里不占额外显存（view/指针，不复制数据）

B = torch.stack([m.mlp.weight for m in self.lora_B[active].loraB], dim=0)
# 每个 B 是 (d_out, r_per) = (4096, 16)
# stack 8 个 → (N, d_out, r_per) = (8, 4096, 16)

② _moe_lora_compute：2 个 einsum + 加权求和

# ── _moe_lora_compute() 独立函数（行 ~296）────────────────────
# 参数：
#   lora_x : (B, T, d_in)  = (4, 500, 4096)  输入
#   A      : (N, r_per, d_in) = (8, 16, 4096) A 权重
#   B      : (N, d_out, r_per) = (8, 4096, 16) B 权重
#   router : (B, T, N)    = (4, 500, 8)  路由权重（softmax 后）
#   scaling: float        = 1.0

# ─── Einsum 1：A 投影 ────────────────────────────────────────
out_A = torch.einsum('bti,nri->btnr', lora_x, A)
# 输入：lora_x (B,T,i=d_in), A (N,r=r_per,i=d_in)
# 输出：out_A (B,T,N,r=r_per) = (4, 500, 8, 16)
# 含义：对每个 batch、每个 token、每个专家，计算 A_n @ x_t
# 等价于：out_A[b,t,n,:] = A[n,:,:] @ lora_x[b,t,:]

# ─── Einsum 2：B 投影 ────────────────────────────────────────
out_B = torch.einsum('btnr,nor->btno', out_A, B)
# 输入：out_A (B,T,N,r=r_per), B (N,o=d_out,r=r_per)
# 输出：out_B (B,T,N,o=d_out) = (4, 500, 8, 4096)
# 含义：对每个 batch、token、专家，计算 B_n @ (A_n @ x_t)
# 等价于：out_B[b,t,n,:] = B[n,:,:] @ out_A[b,t,n,:]

# ─── 加权求和：按 router 权重聚合 8 个专家输出 ─────────────
return (out_B * router.unsqueeze(-1)).sum(dim=2) * scaling
# router.unsqueeze(-1): (B,T,8) → (B,T,8,1)，广播到 (B,T,8,4096)
# out_B * router.unsqueeze(-1): 每个专家的输出乘以其路由权重
# .sum(dim=2): 在 N=8 这个维度求和 → (B, T, 4096)
# * scaling: 乘以 lora_alpha/r 的缩放因子
# 最终 shape: (B, T, d_out) = (4, 500, 4096)
关键变化：16 次 kernel 变为 2 次
  • 原始：16 次 CUDA kernel（8 × loraA + 8 × loraB）
  • 向量化：2 次 einsum kernel，GPU 一次性处理所有 8 个专家的矩阵乘法
  • 矩阵变大：从 8×(B,T,16)@(16,4096) 变成一次 (B,T,8,16)@(8,16,4096)，GPU 利用率更高

einsum 符号详解 — 从零理解

torch.einsum(subscript, A, B) 用字母代表维度，通过下标公式描述张量运算。 规则：出现在输入但不在输出里的字母 → 在那个维度上求和（收缩）。

einsum vs matmul：什么时候用 einsum？
  • matmul/@：只能做 (..., m, k) × (..., k, n) 的标准矩阵乘法
  • einsum：可以自由指定哪些维度收缩、哪些保留、哪些广播，表达力更强
  • 这里用 einsum 的原因：输入是 3D/4D，需要"对每个专家分别做矩阵乘"——einsum 比 for + matmul 更清晰也更高效
  • 底层 PyTorch 会把 einsum 编译为 bmm（批量矩阵乘）或 contraction，仍然是单次 CUDA kernel
06

为什么更快 — GPU 执行模型

原始 Loop（慢）
# 每次迭代：
# 1. Python 解释器进入循环
# 2. CPU 向 CUDA 发送 kernel 调用请求
# 3. GPU 执行 (16,4096) × (B,T,4096)
#    → 矩阵太小，SM 大量空转
# 4. GPU → CPU 同步（等待结果）
# 5. 重复 16 次

# 时间线（粗略）：
# CPU: [py][kernel₁][py][kernel₂]...×16
# GPU:  ──[k₁]──  ──[k₂]──  ...×16
#           ^ 空隙：等待 CPU dispatch
向量化 einsum（快）
# 2 次 kernel：
# 1. CPU dispatch einsum₁
#    GPU 执行 (8,16,4096) × (B,T,4096)
#    → 矩阵 8× 大，SM 高利用率
# 2. CPU dispatch einsum₂
#    GPU 执行 (B,T,8,16) × (8,4096,16)
# 完成

# 时间线（粗略）：
# CPU: [py][einsum₁][einsum₂]
# GPU:  ──────[E₁]──────[E₂]──
#               ^ 更长，但只有 2 个

关键洞察：矩阵越大，GPU 越高效

GPU 并行计算的开销主要来自两部分：kernel 启动开销（固定，约 5～20μs/次）和 计算本身。当矩阵很小时（如 16×4096），计算时间短到和启动开销相当， GPU core 大量空转。向量化把 8 个 (16, 4096) 合并成 (8×16, 4096) 等效的大矩阵， GPU 一次性打满。

对比项原始 Loop向量化 einsum
CUDA kernel 调用次数16 次（8 A + 8 B）2 次
Python 解释器开销8 次 for 循环迭代0（纯张量操作）
单次矩阵尺寸（A 投影）(B,T,16) @ (4096,16)^T 每次(B,T,8,16) @ (8,16,4096) 合并
显存读写次数8 对 (read A, write mid, read B, write out)1 次读全部 A + 1 次读全部 B
实测推理加速（batch=1）1.0×（基准）1.48～1.61×
实测训练加速（ZeRO-3）1.0×（基准）~1.0×（通信开销主导，LoRA 占比 <1%）

在正式 Eval 中使用

向量化 forward 通过环境变量控制，默认开启，无需修改代码。

控制方式

# 默认：向量化开启（推荐，推理更快）
CUDA_VISIBLE_DEVICES=6 python -m ETrain.Eval.LLaVA.CoIN.model_vqa_science \
    --model-path ... --batch-size 4 ...

# 显式开启
COIN_USE_VECTORIZED_LORA=1 python ...

# 回退原始 loop（用于对比测试或排查问题）
COIN_USE_VECTORIZED_LORA=0 python ...
前提条件：必须使用 optimize 分支的 coinmoelora.py

MoEMoKA 分支（main）无向量化代码，即使设 COIN_USE_VECTORIZED_LORA=1 也无效（变量不存在）。 使用前确认：git branch 显示 * optimize， 或 git show HEAD:CoIN/peft/tuners/coinmoelora.py | grep vectorized 有输出。
